# Claude Code's evolution from tool to machine mirrors the historical transition from craft to industrial machinery

A concrete case study in the political economy of software. Early versions of Claude Code presented legible affordances: a user could look at the interface and immediately understand what actions were available, how to invoke them, and what the system would do. This is the phenomenology of tool-use — the tool is transparent to the user's intention. The user remains the primary agent; the tool extends their capacity.

Later versions exhibit a different character. Functionality expands, but the expansion is toward automation and background operation. New features run processes the user does not see, make decisions the user does not directly control, and operate on timescales and in domains that feel autonomous. The user no longer looks at the tool and immediately knows how to deploy it. Instead, the tool operates, and the user supervises — or simply observes.

This trajectory mirrors what Marx analyzed in the transition from handicraft to manufacture to machinery. In craft production, skill resides in the worker; the tool extends it. In manufacture, tasks are divided and partially mechanized, but skilled workers remain central. In factory production, the machine sets the pace and logic; the worker adapts to the machine's rhythm. The skill migrates from the individual to the apparatus. What was distributed across many skilled workers becomes crystallized in mechanical form.

The parallel is not metaphorical. Claude Code's increasing automation represents the absorption of what were once explicit user skills — knowing how to prompt, how to break tasks down, how to guide the model — into the system itself. The system now does the prompting, the decomposition, the guidance. The user's deliberate skill is displaced by the machine's systematized procedure.

The note does not treat this as a design failure. It is a structural tendency: capital-owned AI systems have incentives to maximize automation and minimize user skill-dependency, because an apparatus that runs without specialized user knowledge is more scalable.
